# 08-02: UI de Miembros del Proyecto

**Phase:** 8 — Completion
**Requirement:** PRJ-02, PRJ-06
**User Stories:** HU-07
**Tipo:** Frontend (backend ya existe)

## Context

El backend tiene el endpoint `POST /projects/<id>/invite/` (invita usuarios existentes por email)
y `ProjectDetailSerializer` devuelve `members` con rol. El frontend NO tiene UI para invitar
miembros ni para gestionar el equipo. `TaskDetailDrawer` ya usa `project.members` para asignar tareas.

## Archivos existentes relevantes

- `backend/apps/projects/views.py` — `invite` action (valida que el usuario exista)
- `backend/apps/projects/serializers.py` — `InviteMemberSerializer` (email + role, no permite 'owner')
- `frontend/src/types/project.ts` — tipo `Member`
- `frontend/src/components/kanban/TaskDetailDrawer.tsx` — usa `project.members`
- `frontend/src/components/Modal.tsx`

## Proposed Changes

### [MODIFY] `frontend/src/api/projects.ts`
- `inviteMemberApi(projectId, email, role)` → `POST /v1/projects/<id>/invite/`
- `updateMemberRoleApi(...)` → si el backend lo soporta (verificar; si no, agregar endpoint PATCH)
- `removeMemberApi(...)` → verificar si existe endpoint DELETE para members

### [NEW] `frontend/src/components/projects/TeamPanel.tsx`
Panel/drawer de gestión de equipo (accesible desde ProjectsPage o KanbanPage):
- Lista de miembros: avatar, nombre, email, rol, fecha de ingreso
- Formulario de invitación: email + selector de rol (admin/developer/viewer)
- Solo Owner/Admin ven los controles de gestión
- Cambiar rol de un miembro (dropdown)
- Remover miembro (con confirmación)

### [MODIFY] `frontend/src/pages/KanbanPage.tsx` o `ProjectsPage.tsx`
Agregar botón "Equipo" que abra `TeamPanel`.

## Task Breakdown

## Notes
- `InviteMemberSerializer` solo permite invitar usuarios YA registrados (valida existencia). No hay flujo de invitación por email a externos — esto es by-design del backend actual.
- Roles disponibles: `owner`, `admin`, `developer`, `viewer`. No se puede invitar como `owner`.
